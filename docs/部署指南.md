# 部署指南

## 1. 风扇控制工具 — systemd 部署

### 1.1 install.sh 脚本

脚本路径：`scripts/install.sh`

脚本功能：
1. 检查运行环境（root 权限、Node.js、pnpm）
2. 安装项目依赖并构建
3. 创建 systemd service 文件
4. 启用并启动服务

```bash
#!/bin/bash
set -euo pipefail

# 检查 root 权限
if [ "$EUID" -ne 0 ]; then
  echo "请以 root 用户运行此脚本"
  exit 1
fi

# 配置
INSTALL_DIR="/opt/power-fan"
SERVICE_NAME="power-fan-control"
NODE_USER="root"

# 检查 Node.js
if ! command -v node &> /dev/null; then
  echo "错误：未找到 Node.js，请先安装 Node.js 24+"
  exit 1
fi

# 检查 pnpm
if ! command -v pnpm &> /dev/null; then
  echo "错误：未找到 pnpm，请先安装 pnpm"
  exit 1
fi

# 获取项目根目录
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_DIR="$(dirname "$SCRIPT_DIR")"

# 安装依赖并构建
echo "安装依赖..."
cd "$PROJECT_DIR"
pnpm install
pnpm --filter @power-fan/fan-control-server build

# 交互式获取 ESP32_HOST
read -p "请输入 ESP32 风扇控制器 IP 地址: " ESP32_HOST
read -p "请输入监听端口 (默认 3001): " PORT
PORT=${PORT:-3001}

# 创建 systemd service
cat > /etc/systemd/system/${SERVICE_NAME}.service << EOF
[Unit]
Description=Power Fan Control Service
After=network.target

[Service]
Type=simple
User=${NODE_USER}
WorkingDirectory=${PROJECT_DIR}/packages/fan-control-server
Environment=ESP32_HOST=${ESP32_HOST}
Environment=ESP32_PORT=8888
Environment=PORT=${PORT}
ExecStart=$(which node) ${PROJECT_DIR}/packages/fan-control-server/dist/index.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

# 启用并启动
systemctl daemon-reload
systemctl enable ${SERVICE_NAME}
systemctl start ${SERVICE_NAME}

echo "安装完成！"
echo "服务状态: systemctl status ${SERVICE_NAME}"
echo "访问地址: http://localhost:${PORT}"
```

### 1.2 使用方式

```bash
# 赋予执行权限
chmod +x scripts/install.sh

# 以 root 运行
sudo ./scripts/install.sh
```

### 1.3 服务管理

```bash
# 查看状态
systemctl status power-fan-control

# 停止/启动/重启
systemctl stop power-fan-control
systemctl start power-fan-control
systemctl restart power-fan-control

# 查看日志
journalctl -u power-fan-control -f

# 卸载
systemctl stop power-fan-control
systemctl disable power-fan-control
rm /etc/systemd/system/power-fan-control.service
systemctl daemon-reload
```

## 2. 远程开关机工具 — Docker 部署

### 2.1 Dockerfile

路径：`packages/power-server/Dockerfile`

```dockerfile
# 构建阶段
FROM node:24-alpine AS builder

WORKDIR /app

# 启用 pnpm
RUN corepack enable pnpm

# 复制 workspace 配置
COPY pnpm-workspace.yaml package.json ./
COPY packages/tcp-client/package.json packages/tcp-client/
COPY packages/power-server/package.json packages/power-server/
COPY packages/power-web/package.json packages/power-web/

# 安装依赖
RUN pnpm install --frozen-lockfile

# 复制源码
COPY packages/tcp-client packages/tcp-client
COPY packages/power-server packages/power-server
COPY packages/power-web packages/power-web
COPY tsconfig.base.json ./

# 构建
RUN pnpm --filter @power-fan/tcp-client build
RUN pnpm --filter @power-fan/power-web build
RUN pnpm --filter @power-fan/power-server build

# 运行阶段
FROM node:24-alpine AS runtime

WORKDIR /app

RUN corepack enable pnpm

COPY pnpm-workspace.yaml package.json ./
COPY packages/tcp-client/package.json packages/tcp-client/
COPY packages/power-server/package.json packages/power-server/

# 仅安装生产依赖
RUN pnpm install --prod --frozen-lockfile

# 复制构建产物
COPY --from=builder /app/packages/tcp-client/dist packages/tcp-client/dist
COPY --from=builder /app/packages/power-server/dist packages/power-server/dist
COPY --from=builder /app/packages/power-server/public packages/power-server/public

EXPOSE 3002

WORKDIR /app/packages/power-server
CMD ["node", "dist/index.js"]
```

### 2.2 docker-compose.yml

路径：项目根目录 `docker-compose.yml`

```yaml
services:
  power-server:
    build:
      context: .
      dockerfile: packages/power-server/Dockerfile
    ports:
      - "3002:3002"
    environment:
      - ESP32_HOST=192.168.1.100
      - ESP32_PORT=8888
      - PORT=3002
    restart: unless-stopped
    # 如需访问宿主机网络上的 ESP32，可使用 host 模式
    # network_mode: host
```

### 2.3 使用方式

```bash
# 构建并启动
docker compose up -d

# 查看日志
docker compose logs -f

# 停止
docker compose down

# 重新构建
docker compose up -d --build
```

### 2.4 配置说明

- 修改 `docker-compose.yml` 中的 `ESP32_HOST` 为你的 ESP32 IP 地址
- 如果 ESP32 在宿主机局域网中，Docker 容器默认使用 bridge 网络可能无法访问
- 解决方案：
  - 方案一：使用 `network_mode: host`（Linux 推荐）
  - 方案二：配置 Docker bridge 网络的子网与局域网一致

## 3. WiFi 配置工具 — 本地运行

无需部署，直接在开发者电脑上运行：

```bash
# 安装依赖
pnpm install

# 构建
pnpm --filter @power-fan/wifi-config build

# 运行
pnpm --filter @power-fan/wifi-config start
```

## 4. 开发模式

### 4.1 风扇控制工具开发

```bash
# 终端1：启动后端（watch 模式）
pnpm dev:fan

# 终端2：启动前端（Vite dev server）
pnpm --filter @power-fan/fan-control-web dev
```

前端开发服务器代理 API 和 WebSocket 到后端，访问 Vite 提供的地址（如 `http://localhost:5173`）。

### 4.2 远程开关机工具开发

```bash
# 终端1：启动后端
pnpm dev:power

# 终端2：启动前端
pnpm --filter @power-fan/power-web dev
```

### 4.3 构建全部

```bash
pnpm build
```

按依赖顺序构建所有包：tcp-client → 前端 → 后端。
