# 风扇控制工具设计

## 1. 概述

风扇控制工具运行在需要控制风扇的电脑上，实时采集 CPU/GPU/机箱温度，根据用户自定义的 JavaScript 表达式控制 3 个风扇的开关和转速。分为后端（Express）和前端（Vue 3）两个包。

## 2. 包信息

| 包名 | 路径 | 类型 |
|------|------|------|
| `@power-fan/fan-control-server` | `packages/fan-control-server` | Express 后端 |
| `@power-fan/fan-control-web` | `packages/fan-control-web` | Vue 3 前端 |

### 3.3 温度采集

- **采集频率**：每 1 秒采集一次
- **CPU 温度**：通过 `systeminformation` 库获取 CPU 温度
- **GPU 温度**：通过 `@rh-ai-bu/ts-nvml` 获取 NVIDIA GPU 温度（暂不考虑多块 GPU）
- **机箱温度**：通过 ESP32 TCP 客户端 `getTemperature()` 获取
- **变量单位**：全部转换为摄氏度浮点数

```typescript
interface TempData {
  cpuTemp: number;    // °C
  gpuTemp: number;    // °C
  caseTemp: number;   // °C
  timestamp: number;  // Unix ms
}
```

### 3.4 表达式引擎

#### 表达式结构

每个风扇有 2 个独立表达式，共 6 个表达式：

| 表达式 | 输入变量 | 返回值类型 | 说明 |
|--------|---------|-----------|------|
| 风扇1 开关 | `cpuTemp`, `gpuTemp`, `caseTemp` | `boolean` | `true`=开, `false`=关 |
| 风扇1 转速 | `cpuTemp`, `gpuTemp`, `caseTemp` | `number` (0-255) | PWM 占空比 |
| 风扇2 开关 | 同上 | `boolean` | |
| 风扇2 转速 | 同上 | `number` (0-255) | |
| 风扇3 开关 | 同上 | `boolean` | |
| 风扇3 转速 | 同上 | `number` (0-255) | |

#### 执行方式

- 使用 `new Function()` 在受限上下文中执行表达式
- 传入变量：`cpuTemp`、`gpuTemp`、`caseTemp`（均为摄氏度浮点数）
- 开关表达式返回值通过 `Boolean()` 转换
- 转速表达式返回值通过 `Math.max(0, Math.min(255, Math.round(value)))` 钳位到 0-255

```typescript
// 表达式执行示例
const fn = new Function('cpuTemp', 'gpuTemp', 'caseTemp', `return ${expr}`);
const result = fn(tempData.cpuTemp, tempData.gpuTemp, tempData.caseTemp);
```

#### 默认表达式

| 表达式 | 默认值 |
|--------|--------|
| 风扇1 开关 | `cpuTemp > 40` |
| 风扇1 转速 | `Math.min(255, Math.max(0, (cpuTemp - 40) * 8))` |
| 风扇2 开关 | `gpuTemp > 40` |
| 风扇2 转速 | `Math.min(255, Math.max(0, (gpuTemp - 40) * 8))` |
| 风扇3 开关 | `caseTemp > 35` |
| 风扇3 转速 | `Math.min(255, Math.max(0, (caseTemp - 35) * 10))` |

#### 表达式持久化

- 表达式保存在后端 JSON 文件中（`~/.power-fan/expressions.json` 或运行目录下 `expressions.json`）
- 通过 API 存取
- 后端启动时加载上次配置，不存在则使用默认表达式

### 3.5 风扇控制循环

```
每 1 秒：
  1. 采集 CPU/GPU/机箱温度
  2. 对每个风扇执行开关表达式 → 调用 setFanSwitch()
  3. 对每个风扇执行转速表达式 → 调用 setFanPwm()
  4. 读取 3 个风扇的实际 RPM
  5. 通过 WebSocket 推送温度 + RPM 数据给前端
```

- 控制循环在 TCP 客户端连接成功后启动
- 断开连接时暂停控制循环，重连后恢复
- 表达式执行出错时记录日志，保持上一次的控制状态不变

### 3.6 REST API

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/expressions` | 获取当前 6 个表达式 |
| `PUT` | `/api/expressions` | 更新表达式（保存并持久化） |
| `POST` | `/api/expressions/test` | 测试表达式（传入模拟温度，返回计算结果） |
| `GET` | `/api/fans/rpm` | 获取 3 个风扇当前 RPM |
| `POST` | `/api/fans/:fanId/switch` | 手动控制风扇开关（覆盖表达式） |
| `POST` | `/api/fans/:fanId/pwm` | 手动控制风扇 PWM（覆盖表达式） |
| `GET` | `/api/status` | 获取系统状态（连接状态、当前温度等） |

### 3.7 WebSocket

- 路径：`ws://host:3001/ws`
- 每秒推送数据：

```typescript
interface WsMessage {
  type: 'temp_rpm';
  data: {
    temps: { cpuTemp: number; gpuTemp: number; caseTemp: number };
    fans: { fanId: number; rpm: number; on: boolean; pwm: number }[];
    timestamp: number;
  };
}
```

- 连接建立时立即推送一次当前状态

### 3.8 前端静态文件

- 前端构建产物复制到 `fan-control-server` 的 `public/` 目录
- 通过 `express.static` 提供服务
- 访问 `http://host:3001/` 即可打开前端界面

### 4.3 组件说明

- **TempDisplay**：通过 WebSocket 实时显示 CPU/GPU/机箱温度，带趋势图
- **FanRpmDisplay**：通过 WebSocket 实时显示 3 个风扇的 RPM 和 PWM 值
- **ExpressionEditor**：6 个文本输入框，支持测试和保存
- **FanManualControl**：手动开关和 PWM 滑块，调用 REST API

### 4.4 构建产物集成

- `vite.config.ts` 中配置 `build.outDir` 指向 `../fan-control-server/public`
- 构建后静态文件直接由后端提供
- 开发模式下通过 Vite proxy 代理 API 和 WebSocket 到后端
